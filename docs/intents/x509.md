# X.509: check a certificate before signing

Use this module with a DER **TBSCertificate**: the certificate body that a CA is
about to sign. Pass the DER-encoded body to this API.

Goal: allow a version 3 end-entity certificate with server authentication enabled,
only the DNS name `api.example.com`, no IP SANs, and a validity period of at most
90 days. Add the remaining checks required by your CA's issuance profile.

## What the policy reads

A simplified decoded view:

```json
{
  "version": 3,
  "validity": {"notBefore": "2026-01-01T00:00:00Z", "notAfter": "2026-02-01T00:00:00Z"},
  "extensions": {
    "basicConstraints": {"cA": false},
    "extKeyUsage": {"serverAuth": true},
    "subjectAltName": {"present": true, "dnsNames": ["api.example.com"], "ipAddresses": []}
  }
}
```

The module produces these fields from DER; the JSON above only shows which fields
the policy uses.

## Complete authority

```yaml
schemaVersion: verdict.authority/v1
id: com.acme.x509.server
type: x509.tbs-certificate
version: 1.0.0
config: {}
policy:
  id: server-name-and-validity
  fallback: DENY
  variables:
    allowedDnsNames: [api.example.com]
  allow:
    - id: named-server
      where:
        - "version == 3"
        - "!extensions.basicConstraints.cA"
        - "extensions.extKeyUsage.serverAuth"
        - "extensions.subjectAltName.present"
        - "lists.nonEmpty(extensions.subjectAltName.dnsNames)"
        - "lists.hasOnly(extensions.subjectAltName.dnsNames, allowedDnsNames)"
        - "lists.isEmpty(extensions.subjectAltName.ipAddresses)"
        - "time.before(validity.notBefore, validity.notAfter)"
        - "time.durationSeconds(validity.notBefore, validity.notAfter) <= 7776000"
```

Download [x509-server.yaml](../authority/examples/x509-server.yaml).
`7776000` is 90 × 24 × 60 × 60 seconds. `nonEmpty` plus `hasOnly` means at least one
DNS name and no unlisted DNS names. Checking only that `api.example.com` is present
would also allow extra names.

| Certificate request                               | Result |
|---------------------------------------------------|--------|
| The view above                                    | ALLOW  |
| Also requests `other.example.com`                 | DENY   |
| Empty DNS SAN list                                | DENY   |
| Requests an IP SAN                                | DENY   |
| CA certificate (`cA: true`)                       | DENY   |
| Validity longer than 90 days, or end before start | DENY   |

Add issuer, subject public-key algorithm/size, key usage, other SAN types and extension
conditions for your issuance profile. Other SAN categories and EKUs pass this example.
Add time checks to constrain issuance dates. The caller verifies name ownership and
issuer identity. Available policy fields are listed below.

## API and field reference

Artifact: `org.exploit.verdict:x509`.

Intent type: `x509.tbs-certificate`.

## Purpose

`TbsCertificateIntent` exposes RFC 5280 `TBSCertificate` data for pre-issuance policy checks.

It parses the to-be-signed certificate body. The caller handles certificate signatures.

## Java

```java
TbsCertificateIntent intent = TbsCertificateIntent.fromDerBase64(tbsCertificateDer64);
```

Builder input is also supported for issuer-side construction. This snippet shows
builder syntax; add the extensions required by the server policy before evaluation:

```java
TbsCertificateIntent intent = TbsCertificateIntent.builder()
    .version(3)
    .issuer("CN=Example CA,O=Example")
    .subject("CN=api.example.com,O=Example")
    .validity(notBefore, notAfter)
    .subjectPublicKey(publicKey)
    .keyUsage(true, "digitalSignature", "keyEncipherment")
    .build();
```

## Root Fields

- `encodedDerHex`, `encodedSha256`
- `version`
- `serialNumber`
- `signature`
- `issuer`, `subject`
- `validity`
- `subjectPublicKeyInfo`
- `issuerUniqueID`, `subjectUniqueID`
- `extensions`

## Rejections

- `invalid_tbs_certificate`
